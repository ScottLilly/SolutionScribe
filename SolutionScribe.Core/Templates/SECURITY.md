## Reporting a Vulnerability

**Please do not report a security vulnerability in a public issue, pull request, or discussion.** A public report tells everyone about the problem before there is a fix for it.

Report it privately instead:

- Use [GitHub's private vulnerability reporting](https://github.com/[your-user-name]/[your-repo-name]/security/advisories/new), on the repository's Security tab. [Turn this on first under Settings > Security > Private vulnerability reporting, or delete this line and leave the email address below.]
- Or email [your-security-email-address].

Include whatever you have: the affected version, what an attacker could do with it, and the steps to reproduce it. A proof of concept helps, but do not let a missing one stop you from reporting.

### What to expect

- An acknowledgement that the report arrived, within [number] business days.
- A decision on whether the report is accepted, and an update at least every [number] days while it is open.
- If it is accepted: a fix in a release, a security advisory, and credit to you in that advisory unless you would rather not be named.
- If it is declined: an explanation of why.

Please give us [number] days to release a fix before describing the vulnerability publicly.
